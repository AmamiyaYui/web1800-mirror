# web1800 前端监控与交互优化实施交接方案

> **非规范审计档案（2026-08-10）**：本文件保留当时的问题证据、方案和验收口径；第三轮代码审计已闭环。当前状态与延期项只看 `../../status.md`，不得把本文件的旧待办重新当成现行范围。

**Goal：** 让玩家能够快速发现资源、人口、生产和物流异常，理解原因，定位对应建筑，执行修复，并看到状态恢复。

**Architecture：** 保持 `src/engine/` DOM-free。引擎负责提供稳定的监控数据和结构化状态原因；`src/ui/` 负责信息层级、中文解释与诊断操作；`src/main.js` 只负责浏览器输入、选中态和相机协调。

**Tech Stack：** 原生 JavaScript、Canvas、DOM/CSS、Node `node:test`；零运行时依赖。

## 1. 审计基线

审计日期：2026-08-10  
审计版本：本地静态资源 `v98`  
审计视口：1258×622、1000×622、800×622  
实际流程：欢迎层 → 仓库 → 原木厂 → 住宅 → 查看 → 铺路 → 移动  
浏览器 JavaScript 错误：0

本次审计只采集证据，没有实施下列优化。

### 核心结论

当前不是“数据显示不足”，而是：

1. 大量资源数据平铺，关键资源被埋没。
2. 状态只有结果，没有可操作的原因。
3. 异常统计不能定位建筑。
4. 操作模式提示与真实行为存在不一致。
5. 建筑详情会显示过期数据。

目标闭环：

```text
发现异常 → 理解原因 → 定位建筑/道路 → 执行修复 → 看到状态恢复
```

## 2. 高优先级审计项

### H-01：修正资源 `/min` 监控口径

**玩家症状：** 周期生产建筑的速率在 `0/min` 与巨大瞬时值之间跳动。

**证据：** `src/engine/tick.js` 的 `state.rates` 只保存当前 tick 流量，`src/ui/economy.js` 直接乘 60。例如每 60 秒产出 1，真实是 `1/min`，当前会显示一帧 `60/min`、其余时间 `0/min`。

**候选文件：**
- `src/engine/state.js`
- `src/engine/tick.js`
- `src/ui/economy.js`
- `tests/engine.test.mjs`

**推荐交互：** 显示最近 30～60 秒滚动平均，或稳定的周期理论产能；必要时用 `≈` 表示平滑值。

**AC：**
- 60 秒产出 1 的稳定链显示约 `+1.0/min`。
- 不在 `0` 和 `+60` 之间跳变。
- 输入消耗、需求消耗、收入统一口径。
- 暂停时保持最后稳定值，不归零。

---

### H-02：资源栏改为“关注资源 + 折叠完整库存”

**玩家症状：** 开局 63 种资源全部展示，大量未解锁资源为 0；实际拥有的鱼不在首屏。

**证据：** 1258×622 下左栏可视高度 472px；开局内容高度 1481px，有人口后 1623px。

**候选文件：**
- `src/ui/economy.js`
- `style.css`

**推荐结构：**

```text
当前关注：金币 / 木材 / 鱼 / 负增长 / 即将耗尽
▼ 建材
▼ 当前阶层需求
▶ 原料
▶ 未解锁资源
```

**AC：**
- 开局不滚动即可看到金币、木材、鱼。
- 未解锁阶层资源默认隐藏或折叠。
- 负增长、库存为零、即将耗尽资源自动进入“关注”。
- 保留一键查看完整库存。
- 默认内容高度不超过一个侧栏视口。

---

### H-03：拆分建筑停工原因并全部中文化

**玩家症状：** 原木厂显示“等待原料/劳动力”，但真实原因可能是劳动力、输入、道路、仓库覆盖或可开发度；详情还显示 `log×1`、`farmers:5`、`market`、`bar` 等内部 ID。

**候选文件：**
- `src/engine/economy.js`
- `src/ui/panels.js`
- `src/ui/economy.js`
- `tests/engine.test.mjs`

**推荐数据形态：** 状态同时提供 `status`、`reason`、结构化细节，例如 `workforce-shortage`、`input-shortage`、`warehouse-out-of-range`、`road-disconnected`、`development-too-low`。

**AC：**
- 每栋停工建筑显示一个明确主因。
- 显示“需要多少 / 当前多少 / 下一步做什么”。
- 商品、人口和服务名称全部中文化。
- 原因变化后一个 tick 内更新。
- 各原因至少有一个顶层协调器或引擎集成测试。

---

### H-04：异常列表可点击定位，并修复小地图遮挡

**玩家症状：** “等待/断连”只是普通文本，不能展开、定位或切换异常建筑；小地图实际不可见。

**证据：** 1258×622 下小地图为 `(1108,386,136×136,z=9)`，右栏为 `(1014,52,232×474,z=10)`，两者完全重叠。

**候选文件：**
- `src/ui/panels.js`
- `src/ui/minimap.js`
- `src/main.js`
- `style.css`

**推荐交互：** 点击“等待 N”展开异常建筑；点击条目后相机居中、地图闪烁、打开建筑详情；支持上一栋/下一栋。

**AC：**
- 统计入口可点击、可键盘聚焦。
- 点击后相机准确定位建筑并打开详情。
- 多栋异常建筑可循环查看。
- 小地图中心顶层元素必须是小地图自身。
- 1258×622 下小地图完整可见且可点击。

---

### H-05：选中建筑详情实时刷新

**玩家症状：** 住宅详情显示 `3/10` 后，即使实际住户下降到约 `1.95`，详情仍显示 `3/10`。

**根因位置：** `src/main.js` 的 `redraw()` 更新经济、目标、日志和统计，但不重新渲染当前选中建筑；当前也没有稳定保存 selected building id。

**候选文件：**
- `src/main.js`
- `src/ui/panels.js`

**AC：**
- 状态、住户、效率、库存、周期进度一个 tick 内同步。
- 建筑被拆除后立即显示“已拆除”或清空选择。
- 玩家不需要重新点击建筑。

---

### H-06：修复建造/移动模式的持续反馈与错误说明

**玩家症状：** 选择仓库后按钮不高亮，没有持续显示“正在放置仓库”；成功后仍留在批量建造模式但无提示。

**已确认不一致：** 移动 Toast 声称“R 旋转，右键/换工具取消”，实际 `move:b2` 状态下右键后仍为 `move:b2`，R 前后旋转均为 0。

**候选文件：**
- `src/main.js`
- `src/ui/mode.js`
- `src/ui/build-menu.js`
- `index.html`
- `style.css`

**推荐模式条：**

```text
正在放置：仓库｜💰500 🪵10｜R 旋转｜Esc 取消｜批量建造：开
```

**AC：**
- 当前建筑按钮或模式条持续高亮。
- 成功建造后明确说明继续批量建造或退出方法。
- `Esc` 统一取消建造、移动、铺路、拆除。
- 若保留“右键取消”，右键单击必须真实取消；否则删除文案。
- 移动模式 R 必须真实旋转；否则删除文案。
- UI 说明与实际键位完全一致。

---

### H-07：解决 1000px 级桌面侧栏/底栏重叠

**证据：** 1000×622 下底栏高 147px、顶部 475px，侧栏底部 526px，重叠 51px；800×622 下地图横向可操作宽度只剩 312px。

**候选文件：**
- `style.css`
- `index.html`

**推荐交互：** 约 1100px 以下左右栏变为可折叠抽屉；底部建筑分类固定单行或分类内部横向滚动；侧栏 bottom 不再写死 96px。

**AC：**
- 1000×622 下底栏与侧栏重叠为 0。
- 所有建造按钮可访问。
- 地图可操作区域尽量保留至少约 560px 宽。
- 侧栏折叠后异常徽标仍可见。

## 3. 中优先级候选

### M-01：人口与需求解释
- 显示人口变化方向和 `/min` 趋势。
- 显示目标住户、需求缺口、服务未覆盖原因。
- 资源负增长时显示预计耗尽时间。
- 需求行提供“查看生产链”。

### M-02：住宅升级条件清单
- 主动显示满员、基础需求、材料的逐项 `✅/❌`。
- 条件未满足时禁用升级按钮，而不是点击后才报错。

### M-03：建造菜单可读性
- `coin:500 wood:10` 改为 `💰500 🪵10`。
- 禁用建筑显示具体缺口。
- 锁定阶层显示解锁阈值。
- 内容继续增加后再做搜索、最近使用或常用固定。

### M-04：经济收支解释
- 金币展开后显示需求收入、维护费和净变化。
- 负增长资源显示预计耗尽时间。

### M-05：目标可执行
- 目标附带“打开建筑分类”“定位海岸”“定位待连接建筑”等操作。

### M-06：通知分级与去重
- 红：必须处理；黄：即将发生；绿：状态恢复；灰：普通操作记录。
- 同类问题聚合，例如“3 栋建筑缺少原木”。

## 4. 推荐实施轮次

### UI 第 1 轮：操作可信度闭环（优先推荐）

最多选以下四项：

1. H-03 拆分停工原因。
2. H-04 异常定位与小地图修复。
3. H-05 建筑详情实时刷新。
4. H-06 模式反馈及 R/右键/Esc 一致性。

这一轮完成后，玩家应能完成：发现异常 → 理解 → 定位 → 修复 → 看到恢复。

### UI 第 2 轮：监控准确性

1. H-01 稳定 `/min` 口径。
2. H-02 关注资源与折叠库存。
3. M-01 人口/需求趋势和缺口。
4. M-04 收支分解和耗尽时间。

### UI 第 3 轮：紧凑视口与建造效率

1. H-07 响应式侧栏/底栏。
2. M-02 升级条件清单。
3. M-03 建造菜单可读性。
4. M-05/M-06 目标和通知闭环。

## 5. 实施协议

1. 实施对话先读取本文件和 `AGENTS.md` 指定的当前规范。
2. 每轮只选 3～4 项，先登记 Backlog/Requirements/Status 和 AC。
3. 涉及状态原因、趋势数据时先写引擎或协调器测试。
4. `src/engine/` 不得引入 DOM。
5. UI 变更后统一提升 `index.html` 所有资源版本号。
6. 至少验证 1258×622、1000×622、1258×480。
7. 运行 `npm test`、`git diff --check`、浏览器 console 和部署隔离检查。
8. 不提交、推送或部署，除非用户明确要求；如提交，本仓库 commit message 固定为 `Initial commit`。
9. 开发完成后交回 Sol 做独立复审，输出“通过 / 有条件通过 / 不通过”。
