# Requirements — 蒸汽都市

Last updated: 2026-08-11 · Normative: current

> 本文件只描述当前有效要求。旧版本 REQ/AC 流水见 Git 历史与 `history/`，不得用旧规则覆盖本文件。

## P0 核心模拟

- **REQ-01 当前地图基线**：当前运行版新游戏生成可复现的 160×160 单连通主岛(World/Island schema)；边界为水，山脉不可通行；矿脉贴山，黏土位于海岸带；森林地形不再生成。旧 128×128 单岛档按 REQ-34 迁移居中。多岛目标见 REQ-30。
- **REQ-02 多格放置**：建筑 footprint 的每一格都校验边界、占用和地形；grid 记录所有 footprint 格，包括锚点格。
- **REQ-03 中心旋转**：建筑 `x/y` 表示几何中心；四向旋转绕中心，预览、实际放置、移动、渲染和连通判定使用同一 footprint。
- **REQ-04 地形专用建筑**：矿场 footprint 必须完全嵌合对应矿脉；海岸建筑 footprint 必须全水且外侧四邻至少一格陆地。
- **REQ-05 道路连通**：建筑通过道路或相邻建筑网络连接任意仓库；拓扑变化必须使连通缓存失效；断连生产建筑停止生产。
- **REQ-06 多仓库资源池**：所有仓库是同一 `state.resources` 总资源池的接入点；仓库无需彼此互连，不建立独立库存。
- **REQ-07 仓库物流服务**：生产建筑除连通外还必须接触仓库沿道路传播的服务范围；土路半径 34，石板路按 2/3 距离成本传播。
- **REQ-08 生产结算**：生产按建筑周期批量结算；原料、对应阶层劳动力、物流覆盖和开发度共同决定状态与产量；维护费按每分钟数值除以 60 每 tick 扣除。
- **REQ-09 库存守恒**：除显式生产、需求消费、维护、建造、拆除返还和收入外，不得凭空增加或减少资源；每 tick 产出/消耗进入 flow/rates。

## P0 人口、住宅与经济

- **REQ-10 阶层**：农民 0、工人 50、工匠 150 人解锁；工程师/投资人保留完整数据但以 `unlockAt=999999` 暂锁。
- **REQ-11 住宅**：所有住宅为 3×3，容量为 10/20/30/40/50；只能从菜单新建农民住宅，后续阶层通过升级获得。
- **REQ-12 住宅升级**：升级要求该栋住宅满员、当前阶层全部基础需求满足和对应建材；住户随建筑迁移到新阶层。
- **REQ-13 需求**：各阶层需求相互独立；商品消耗 = 当前人口 × 每人口每秒 rate；服务需求按沿道路覆盖住宅比例满足。
- **REQ-14 住户模型**：每个有供应的基础需求离散提供完整 Influx；每阶层人口缓慢趋近所有住宅目标总和，接近目标时精确收敛。
- **REQ-15 幸福度**：奢侈需求按满足度贡献阶层幸福度；全局幸福度按各阶层当前人口加权。
- **REQ-16 需求收入**：每 tick 收入 = `Σ(need.income × 满足度 × 当前人口) ÷ 60`；不得恢复旧“人口×固定税率×幸福度”公式。
- **REQ-17 数值口径**：人工表“消耗/住宅(每秒)”和“收入/住宅(每分钟)”均由生成器除以该阶层住宅容量，得到引擎每人口单位。

## P1 玩家交互与反馈

- **REQ-18 开局**：新游戏为 0 建筑/0 人口，资源为 5000 金币、60 木材、100 鱼([B-59] 用户调整:原 10000/300)；首个目标引导玩家从菜单建造仓库，不设置强制门禁。
- **REQ-19 建筑操作**：提供查看、两阶段移动、铺路、拆除；建造和移动预览支持 R 四向旋转并允许点击绿色 footprint 内任意格按预览锚点落位。
- **REQ-20 道路费用**：土路 3 金币/格；石板路不能直接建造，只能把已有土路按 12 金币/格升级；失败必须退费。
- **REQ-21 信息界面**：展示库存、60 tick 平滑每分钟速率、人口趋势、幸福度、时间、结构化异常、可执行目标、建筑详情、生产链、机制速览、图例和小地图；箭头与数值必须使用同一口径。
- **REQ-22 存档**：localStorage 自动存档；标准旧窗口安全迁移，部分损坏统计窗口归一化且不得产生 `NaN/Infinity`；整体坏档备份原文并回到新游戏；重置前倒计时确认，确认时先禁用 beforeunload 自动保存。
- **REQ-23 社区入口**：公告每次进入可见且可重开；留言 API 不可用时游戏主体继续运行；打赏使用本地固定金额二维码。
- **REQ-24 桌面可用性**：默认桌面视口必须看见可操作岛屿与主要 HUD；紧凑视口不得让顶部控件宽度归零或把开始按钮隐藏得不可发现。

## P0 下一版本：开荒新岛（已批准；B-61已实现并通过第四轮独立复验，B-62～B-65尚未实现）

- **REQ-30 世界规模**：所有正式岛屿统一为 160×160；灰冠首版最多拥有 12 座岛，但存档 schema、实体关系和配置结构不得把 12 写成永久上限。岛屿统一「灰冠岛 N」序列命名([B-62a]：主岛=灰冠岛 1，探索获得的新岛按获得顺序连续编号)。
- **REQ-31 状态所有权**：金币由世界全局共享；商品、人口、建筑、道路、地图和岛内多仓库总资源池按岛隔离；船只和海上任务属于世界层实体。
- **REQ-32 精确模拟**：只渲染当前岛，但所有岛继续使用同一套精确生产、需求、人口和服务语义。世界 tick 逐岛分帧执行，不跳 tick、不冻结离岛；完整世界 tick 结束后才统一结算财政、运输、保存边界和 UI 更新。
- **REQ-33 切岛入口**：顶部提供当前岛下拉框用于快速切换；世界航图覆盖层提供完整岛屿、舰队、运输和探索入口。切岛不得让上一岛的选中建筑、放置/移动工具或镜头状态污染新岛。
- **REQ-34 旧档几何迁移**：旧 128×128 主岛完整复制到 160×160 中央，所有持久化地图坐标统一 `+16,+16`；旧 `(0,0)` 映射到新 `(16,16)`，旧 `(127,127)` 映射到新 `(143,143)`。新增 16 格外圈全部为海水，不生成陆地、矿床、装饰、道路或建筑。
- **REQ-35 迁移幂等与守恒**：迁移不得按 seed 重生中央地图，不改变旧金币、商品、人口、建筑 ID、等级、住户、道路等级或矿床；派生 grid/连通/服务/小地图/渲染缓存迁移后重建。明确 schema 版本保证坐标只平移一次，失败不得覆盖原始旧档。首次执行多岛迁移前，必须把主存档未经改写的原始字符串永久保存到独立键 `web1800-save-v1.pre-multi-island`；该键存在时任何迁移、加载、自动保存、新游戏或清除当前存档均不得覆盖或删除，只有玩家在存档迁移工具中明确恢复或确认永久删除才能操作。备份写入失败时迁移必须中止并保持主存档原样；恢复前先把当前主存档写入普通 `.bak`，该保护写入失败时不得继续恢复。存档迁移工具须支持下载、恢复、永久删除及导出时可选包含该备份。
- **REQ-36 植物禀赋**：植物禀赋只包含 `potato/grain/hops/pepper/grapes`；伐木和羊毛、猪、牛肉等畜牧不占植物槽。旧档主岛固定拥有上述 5 种，作为可超过普通 4 种上限的兼容特例；清单不得使用通配符，未来新增植物不得自动追加。
- **REQ-37 新岛资源选择**：普通正式岛每岛最多 4 种植物、4 种矿物，同种矿物的多组矿床只占 1 个类型槽。新游戏主岛保底土豆、谷物、啤酒花、黏土和铁矿；煤商品可由炭窑获得，煤矿不属于开局保底。探索新岛在世界仍有缺失时，至少补 1 种尚未拥有的植物和 1 种尚未拥有的矿物，其余槽位随机；多个探索同 tick 完成时按稳定任务顺序逐个重算缺失集合。每岛只为入选矿物生成矿床，并沿用现有分级数量：黏土 3～4 组（每组 5×5）、铁 5～6 组、煤 4～5 组、铜 3～4 组、锌 2～3 组、石灰岩 2～3 组、金 1～2 组（后六者每组 3×3）。每组必须完整匹配对应矿场 footprint；任一入选矿物未达到抽定组数或无法完整嵌合时，生成器须使用确定性派生种子在内部重试并最终采用确定性合法兜底，不得向玩家交付缺矿、残块或不可建矿床。旧档主岛只迁移既有矿床，不重生。
- **REQ-38 海事建筑与商品**：新增船帆、制帆厂、码头和帆船造船厂。制帆厂为工人阶层 5×5，500 金币、8 木材、10 砖块、75/min 维护、50 工人，羊毛 1→船帆 1/30 秒，普通平地且支持电力增幅。帆船造船厂为工人阶层 6×17，10000 金币、20 木材、25 砖块、0 钢材、100/min 维护、100 工人，海岸建筑、支持电力增幅、主动订单且每单产出 1 艘。码头为 7×11，2500 金币、10 木材、8 钢材、0 维护、0 劳动力，每岛最多 1 座。
- **REQ-39 通用帆船**：首版只有一种通用帆船；每单消耗全局金币 5000、本岛木材 20、本岛船帆 10，基础工作量 180 个正常世界 tick（3 分钟），维护 15/min；每座造船厂最多 4 份订单（1 份建造＋3 份等待）。提交订单时立即扣除完整费用并保存付款快照和下单岛 ID；任意尚未完工的等待中或建造中订单均可取消，金币和本岛材料按付款快照全额返还到全局钱包和下单岛，已投入工作量清零且不补偿时间。断连、缺工或移动只暂停并保留订单；拆除造船厂自动取消所属未完工订单并按同规则全额返还。船有 2 个货仓槽、每槽原型容量 50；原型航速 4.4～15.8 节仅保留为来源规格，首版不实现风力、顺逆风或速度波动。运输采用持续流，不等待装满、不模拟往返周期、不批量到货；每槽最大 5 单位/min，玩家以 0.1 单位/min 为步长配置，双槽整船最大 10 单位/min。该速率是独立平衡值，不再用“容量 50÷虚构 10 分钟航次”作为依据。航线绑定后，船逻辑停留在来源岛；只允许编辑两个货仓槽的商品与速率，来源岛、目标岛和分配船不可热改，必须取消后重建。编辑、主动暂停、恢复和取消均在下一完整世界 tick 原子生效；暂停保留航线与船只绑定、停止运输并继续支付维护，暂停中仍可编辑。主动暂停与来源码头失效造成的阻塞分开记录：复连只自动解除阻塞，不得自动解除主动暂停；恢复清除主动暂停，若来源码头仍无效则继续阻塞。任意活动、暂停或阻塞航线均可无条件取消；取消不要求有效码头、不收费、不增加返航时间，船在下一完整世界 tick 解绑并成为来源岛的 `idle` 船，既有运输结果不回滚。
- **REQ-40 船只状态与码头权限**：船是有稳定 ID 的实体，不是可堆叠商品。只有停留在岛上的 `idle` 船可以退役；运输、暂停但仍绑定航线、调遣、返回、探索及其他海上状态均禁止退役。退役按该船实际建造付款快照返还 20 木材与 10 船帆、不返还 5000 金币，材料进入船当前停留岛；不要求造船厂、码头或仓库连通。码头只提供出发权限；运输目标岛可以没有码头。来源码头必须建成且经陆侧道路连通本岛任意仓库才有效；断连或移动期间禁止发起新任务，既有来源任务保留并阻塞，复连后自动恢复；拆除码头不删除任务或船，相关来源任务保持阻塞，重建并恢复有效后继续。
- **REQ-41 灰冠调遣**：只有空闲船可以发起调遣；来源岛需要有效码头，目标已拥有岛不要求码头；不收金币或商品，固定 600 个普通世界 tick（10 分钟），途中继续支付维护且不可取消、改目标、运输、探索或退役。
- **REQ-42 近海探索**：探索时长为 10 分钟；暂停游戏仍推进，关闭页面停止。允许主动放弃但不返还，失败损失全部投入。四档总成本为：60%=通用帆船×1；70%=船×1+鱼20+木材10；80%=船×1+鱼40+木材20+工作服10；90%=船×1+鱼60+木材30+工作服20+烈酒20+船帆5；各档金币均为 0，商品从来源岛一次性扣除。**探索档位 UI 必须同时展示成功率与代价([B-68] 玩家反馈)**。
- **REQ-43 新岛取得与初始状态**：探索成功后直接获得新岛，不再支付占领费用，不自动切换；探索发起时即预留 12 岛上限中的名额。获得的灰冠岛初始鱼 100、木材 20、其他商品 0、人口 0、建筑 0；金币继续使用世界全局钱包。本规则不覆盖新游戏主岛或旧档迁移主岛。
- **REQ-44 输入操作与手势([B-66] 玩家反馈)**：地图平移支持右键拖拽与 WASD/方向键按住连续移动(两者并存);滚轮缩放;R 旋转放置朝向;Esc 取消工具。页面层手势做满:全页禁右键菜单、中键自动滚动、拖拽、触控板/触摸手势(touch-action:none)与边缘回弹(overscroll-behavior:none)。浏览器扩展手势插件与系统级手势在页面层无法拦截(安全模型),属已知限制,键盘平移为其替代路径。
- **REQ-45 视口与缩放([B-67] 玩家反馈)**：瓦片尺寸下限放开(不再钳制 32px),视口适配尺寸(fitted);**最小缩放 = 地图恰好贴满视口短边**(动态下限,不再缩到比地图小留白),最大 4 倍;初始视野 = 全图贴边(岛屿整体与海岸线一览,铺海岸建筑无需盲平移)。缩小级别(tile<12px)简化绘制:建筑只画 footprint 色块,跳过名称/状态文字与产出飘字,并用离屏缩略缓存(布局版本 `_layoutVer` 变化才重建,每帧 drawImage)保证全图渲染帧率;放置/拆除/铺路/移动/升级递增布局版本,tick 不递增。
- **REQ-46 岛屿禀赋可见性([B-69] 玩家反馈)**：资源面板(左栏「资源」tab)底部展示当前活动岛的矿物与植物禀赋(`island.deposits` / `island.fertilities`),含中文名与图标;主岛保底(黏土/铁 + 土豆/谷物/啤酒花)与探索新岛禀赋(含随机补缺)均须可查,玩家据此规划矿场/农场布局。
- **REQ-47 区域命名**：四个区域的现实原型与项目原创名称固定为欧洲→「灰冠」、南美洲→「翠湾」、非洲→「曜原」、北极→「霜环」；各区岛屿展示名使用「区域名＋岛 N」序列且与存档实体 ID 分离。本条不定义各区可探索/可拥有岛屿上限，也不定义远洋探索规则。

## P1 工程与发布

- **REQ-25 双端引擎**：`src/engine/` 不依赖 DOM；同一模块同时支持浏览器命名空间和 CommonJS 测试加载。
- **REQ-26 数据生成**：建筑和需求 generated JS 只能由人工核查表生成；变更结构时必须同步生成器、浏览器加载和测试加载。
- **REQ-27 静态缓存**：浏览器资源变更后，`index.html` 中所有 `?v=N` 必须统一递增。
- **REQ-28 部署隔离**：`tools/deploy.sh` 只把运行所需的 index/admin/style/src/assets 放入 `deploy/`；原始表格、内部资料、文档和 Git 元数据不得进入站点。
- **REQ-29 可选后端**：留言板由 Cloudflare Worker + D1 提供；管理员写操作使用 `X-Admin-Key`，密钥不写入仓库或持久化到客户端。
