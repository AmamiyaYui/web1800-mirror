# 开荒新岛决策证据台账

Last updated: 2026-08-12

> 本文件用于防止长对话、`clarify` 按钮回执和上下文压缩造成决策丢失。它记录来源与状态；玩法规范仍以 `requirements.md`、`decisions.md` 和验收 AC 为准。

## 状态口径

| 状态 | 含义 | 能否写入现行规范 |
|---|---|---:|
| `CONFIRMED_EXPLICIT` | 找到用户原文或 `clarify user_response` | 是 |
| `CONFIRMED_RECOVERED` | 原始按钮回执未保存，但后续确认、用户纠错及连续上下文能证明已定 | 是，必须注明恢复来源 |
| `PROPOSED_ONLY` | 只有助手方案；用户没有明确选择 | 否 |
| `OPEN` | 确实尚未确定 | 否 |
| `SUPERSEDED` | 曾经提出或确认，但已被后续决定覆盖 | 否 |

执行顺序固定为：

```text
用户确认
→ 当轮立即更新本台账
→ 同步 requirements / decisions / AC
→ 在对话中复述“已落盘”
→ 再进入下一项
```

用户回复“下一项”只能表示继续推进，不能单独把上一条助手提案升级为 `CONFIRMED_EXPLICIT`。

### 阻断对应子系统实现

无；核心灰冠首版的已知阻断边界均已闭合。

### 可延期，不阻断核心灰冠首版

1. **世界管理扩展**：岛屿放弃、航图是否暂停、命名与重名、航图信息密度、跨岛警告聚合。
2. **性能过载交互**：积压提示、自动降速阈值与恢复规则。

## 每次继续前的检查门

下一项只能从上面的 `OPEN` 清单中取，并且必须先检查：

```text
requirements.md 是否已经写成待定
本台账是否仍是 OPEN
历史中是否存在明确 user_response
是否有后续决定覆盖它
```

确认后必须在同一轮完成：

```text
台账 OPEN → CONFIRMED
requirements / decisions / AC 更新
backlog/status 更新
向用户复述已写入的精确规则
```
