# Decisions — 蒸汽都市

Last updated: 2026-08-12 · Normative: current

> 本文件只保留**当前有效决策**。ADR-001~030 的完整时间流水位于 `history/decision-history.md`，仅供追溯。

## ADR-C01：产品形态与合规

Status: accepted

- 中文展示名为《蒸汽都市》，英文项目/仓库/package 名为 `web1800`
- 产品是桌面优先的浏览器工业时代城市模拟经营游戏，同时是 AI agent 产品工程能力展示
- 使用原创 UI、命名和文本，不发布商业游戏官方美术、角色或受保护文本
- 内部研究资料可描述参考来源，但原始表格和抓取资料不进入静态站点

## ADR-C02：零依赖双端引擎

Status: accepted

- 浏览器使用经典 `<script>`，保证 `file://` 可运行；不引入打包器或运行时框架
- 引擎使用 IIFE，同时挂载 `globalThis.Engine` 和 `module.exports`
- `src/engine/` 保持 DOM-free，Node 测试与浏览器共用同一份逻辑
- 加载顺序不保证的跨模块引用必须在函数体中解析

## ADR-C03：数据源与生成管线

Status: accepted

- 人工核查 Excel 是建筑和需求的可维护生成来源；`buildings-data.js` / `needs-data.js` 为程序运行生成物
- 项目检查以程序实际加载的运行配置、真实读取路径和必要的运行结果为准；人工表、Wiki 和外部原型仅作参考，参考值经用户批准后才成为需求输入
- 需求原表的消耗和收入均为每住宅口径，生成器除以阶层容量得到每人口单位
- 用户自己的核查表不得被自动同步；只有明确指令后才写入原版数值
- generated 文件、生成器、浏览器加载顺序和测试加载顺序必须一起维护

## ADR-C04：空岛随机地图，无森林

Status: accepted

- 新游戏为 160×160 种子化单主岛(World/Island schema；旧 128×128 档迁移居中)，0 建筑、0 道路、0 人口
- [B-62a 命名规则] 全岛统一「灰冠岛 N」序列：主岛正式名「灰冠岛 1」；探索获得的新岛按获得顺序「灰冠岛 2、3…」连续编号(名字与存档 id 分离，探索岛 id 仍为 island-N)。旧 v1 单岛档迁移主岛名与旧 v2 档主岛名('主岛')在加载时统一归一为「灰冠岛 1」。
- 当前运行版开局资源为 5000 金币、60 木材、100 鱼；仓库和住宅都从菜单建造
- 森林地形及相关加成已删除；旧档森林格迁移为平地，平地使用原森林绿色
- 山脉是障碍；铁/铜/金/煤/锌/石灰岩以矿床块贴山，黏土位于海岸带

## ADR-C05：中心锚点与 footprint 真相

Status: accepted

- 建筑 `x/y` 为几何中心，旋转绕中心；偶数尺寸允许中心落在 ±1 格范围
- 所有占用、地形、预览、道路接触、渲染、移动、拆除和升级必须使用同一 footprint
- 海岸建筑全部 footprint 在水里且邻接陆地
- 矿场 footprint 必须完全嵌合对应矿脉
- 移动建筑免费，住户、状态和朝向随建筑保留；失败回滚原位置

## ADR-C06：道路、物流和总资源池

Status: accepted

- 所有仓库都是同一总资源池的接入点；生产建筑连接任意仓库即可，仓库彼此无需互连
- 连通 BFS 从所有仓库 footprint 出发；拓扑变化使惰性缓存失效
- 仓库同时是物流服务建筑；生产还必须接触其道路服务范围
- 土路 3/格、服务成本 1；石板路只从土路升级 12/格、服务成本 2/3
- 服务建筑从 footprint 外圈道路沿道路传播，不使用欧氏半径直接命中住宅

## ADR-C07：住宅、人口、需求和收入

Status: accepted

- 住宅均为 3×3；容量依次 10/20/30/40/50
- 只能新建农民住宅，后续住宅必须逐级升级；升级要求该栋满员、全基础需求和建材
- 每阶层需求独立；消耗按当前人口
- 基础需求采用离散 Influx：有供应即提供完整住户贡献，人口以 2%/tick 向目标趋近并在接近时精确收敛
- 奢侈需求只贡献幸福度
- 收入唯一公式为 `Σ(need.income × satisfaction × current population) / 60` 每 tick
- 旧“总人口×0.3×幸福度”实现已经删除，不得恢复

## ADR-C08：内容开放边界

Status: accepted

- 农民、工人、工匠是当前玩家可推进阶层
- 工程师和投资人数据、住宅与若干生产链保留，但 `unlockAt=999999`
- 在皮草大衣、朗姆酒、咖啡、电力、大学、剧院等缺失需求建筑补齐前，不开放高阶流程
- 当前运行版尚无贸易、多岛、船运、战争、AI 对手、仓库容量和运输车辆模型；多岛与灰冠船运已批准为下一版本方向，见 ADR-C13~C17

## ADR-C09：存档、留言与部署

Status: accepted

- 游戏进度只存 localStorage；每 30 tick 与离开页面时自动保存
- 重置必须先禁用 beforeunload 保存，再清档和重载
- 留言板使用 Cloudflare Worker + D1，是可选联网能力；失败不影响游戏
- 管理操作用 `X-Admin-Key`，客户端只在内存持有，密钥不得进入仓库
- Pages 通过 `tools/deploy.sh` 组装 `deploy/`，只发布运行资产

## ADR-C10：迭代、测试和发布纪律

Status: accepted

- 每轮最多 3~4 个 backlog 项，文档先行并绑定 REQ/AC；完整协议已折入根目录 AGENTS
- 引擎修改先写可失败测试；协调器接线必须有顶层集成测试
- 收尾必须执行 `npm test`、浏览器 smoke、`git diff --check` 并回填 status/backlog；重要审计证据归档到 history
- 浏览器资源修改统一递增所有 `?v=N`
- 本仓库提交信息固定为 `Initial commit`；不改历史、不 force-push

## ADR-C11：紧凑视口采用信息降噪，不改变 T2 桌面布局

Status: accepted

- 保持 Canvas 背景 + 四边 fixed overlay 的 T2 方块地图结构，不进行移动端重构
- 初始相机在装配时定位到地图中心，使随机岛核心区进入首屏
- 约 1680px 以下隐藏顶部低优先级说明标签和开发提示，保留速度、时间及全部操作按钮
- 顶部 section 不允许被 flex 压缩到 0；通过缩小间距/按钮 padding 保持单行
- 欢迎层改为“标题 + 独立滚动正文 + 固定操作区”，开始按钮始终可见

## ADR-C12：监控与修复动作使用结构化、同源数据

Status: accepted

- 资源、收支和人口趋势统一使用 60 tick 平滑窗口；箭头与显示数值不得各算一套
- 存档统计窗口在 load 与 tick 边界归一化，任何展示口径不得出现 `NaN/Infinity`
- 引擎返回结构化停工原因、detail、链段缺失与 `{id,type}` 定位目标；UI 负责中文文案、图标和相机动作
- 目标链按同类型全部实例判断：无实例引导建造、全部断连引导定位/铺路、任一连通即完成

## ADR-C13：多岛所有权与精确模拟

Status: accepted

- 所有正式岛屿统一为 160×160；首版最多 12 座，但数据结构不写死永久上限
- 金币全局共享，商品和人口按岛隔离；船只与海上任务属于世界层
- 只渲染当前岛，所有岛继续精确模拟；逐岛分帧，完整世界 tick 后统一结算财政、运输、保存和 UI
- 顶部当前岛下拉用于快速切换，世界航图覆盖层提供完整世界管理入口

## ADR-C14：旧主岛居中迁移并冻结兼容禀赋

Status: accepted

- 旧 128×128 主岛居中复制到 160×160，所有持久化地图坐标精确 `+16,+16`
- 新增 16 格外圈全部为海水；中央旧地图、建筑、道路、矿床、商品和人口不得重生或重排
- 旧主岛固定拥有 `potato/grain/hops/pepper/grapes`，可超过普通 4 植物上限；不用永久通配符，未来植物不自动追加
- schema 迁移必须幂等、失败不覆盖可用旧档；派生缓存迁移后重建
- 首次多岛迁移前永久保存一份不可自动覆盖的主存档原始字符串到 `web1800-save-v1.pre-multi-island`；写入失败则中止迁移。自动保存、新游戏和清除当前存档不得删除或覆盖，只有玩家可在存档迁移工具中恢复或确认永久删除
- 恢复迁移前原档之前，必须先把当前主存档成功写入普通 `.bak`；工具页提供下载、可选导出、恢复和二次确认删除

## ADR-C15：首版只使用通用帆船与持续运输

Status: accepted

- 首版只有一种通用帆船；订单为 5000 全局金币、20 本岛木材、10 本岛船帆、180 world ticks，每单 1 艘，维护 15/min；每厂最多 4 份订单（1 建造＋3 等待）
- 下单时全额扣款并记录付款快照和下单岛；任意未完工订单取消均全额返还金币与材料，已经投入的工作量清零且不补偿时间。断连、缺工和移动只暂停；拆除造船厂自动取消未完工订单并按同规则返还
- 保留 2 个货仓槽、每槽原型容量 50；4.4～15.8 节仅作原型记录，首版不实现风力和速度波动
- 运输是每世界 tick 持续转移的物流流，不等待装满、不模拟往返周期、不批量到货
- 每槽最大 5 单位/min、配置步长 0.1，双槽整船最大 10 单位/min；被撤回的是“容量50÷虚构10分钟航次”的推导依据，不是最终速率值
- 航线只允许编辑槽位商品与速率，来源、目标和船不可热改；编辑、暂停、恢复、取消都在下一完整世界 tick 生效
- 船绑定航线期间逻辑停留来源岛；主动暂停保留绑定并继续维护，且与码头阻塞独立。取消无需码头、费用或返航时间，船在边界解绑并成为来源岛空闲船

## ADR-C16：码头出发权限与船只状态

Status: accepted

- 码头为 7×11、2500 金币、10 木材、8 钢材、0 维护、0 劳动力，每岛最多 1 座
- 码头只提供出发权限，目标岛可以没有码头；来源码头须建成并经陆侧道路连通任意仓库才有效。断连或移动期间禁止新任务、既有来源任务保留并阻塞，复连自动恢复；拆除不删除任务和船，重建恢复有效后继续
- 只有岛上空闲船可退役；运输、调遣、探索及其他海上状态不能退役。退役按实际付款快照返还 20 木材与 10 船帆、不返 5000 金币，进入当前停留岛；不要求造船厂、码头或连仓
- 灰冠内调遣固定 600 普通世界 tick，来源需有码头、目标无需码头，免费但持续维护且途中不可取消

## ADR-C17：灰冠探索、补缺与新岛初始包

Status: accepted

- 探索暂停时继续、关闭页面停止；失败和主动放弃损失全部投入
- 四档成功率/总成本为 60%船×1；70%加鱼20木10；80%加鱼40木20工作服10；90%加鱼60木30工作服20烈酒20船帆5；金币均为0
- 普通岛每类最多 4 种资源；世界仍有缺失时，新岛至少补 1 种缺失植物和 1 种缺失矿物，其余随机
- 只为入选矿物生成矿床并沿用现有分级数量：黏土3～4组（5×5）、铁5～6、煤4～5、铜3～4、锌2～3、石灰岩2～3、金1～2组（均3×3）
- 每组必须完整匹配矿场；数量不足或无法嵌合时内部确定性重试并使用合法兜底，不允许静默少矿。旧档矿床只平移不重生
- 成功后直接获得新岛、不再付费、不自动切岛；发起时预留 12 岛上限名额
- 新灰冠岛初始鱼100、木材20、其他商品0、人口0、建筑0；全局金币不重置

## ADR-C18：四大区域原创命名

Status: accepted

- 四个区域的现实地理原型依次为欧洲、南美洲、非洲、北极；项目原创名称依次为「灰冠」「翠湾」「曜原」「霜环」
- 岛屿展示名沿用「区域名＋岛 N」序列：灰冠岛 N、翠湾岛 N、曜原岛 N、霜环岛 N；名称与存档实体 ID 分离
- 本决策只冻结区域原型与命名，不自动确定每区可探索/可拥有岛屿上限，也不等同于批准“远洋探索”的解锁、成本、时长、船只、成功率或结算规则

## ADR-C19：区域分配与远洋探索框架（用户拍板 2026-08-12）
- **12 岛分配**：「4422」——灰冠 4 岛（含主岛灰冠岛 1，可探索 3）、翠湾 4 岛、曜原 2 岛、霜环 2 岛；总名额 12 不变，探索按区域计数（该区域未达上限才可探）
- **阶段解锁**：造船厂建成即解锁翠湾；曜原与霜环需要已解锁翠湾（两者彼此无先后）。解锁条件不绑定未开放阶层（工程师/投资人 unlockAt=999999 暂锁）
- **目标区域选择**：探索时可选目标区域（已解锁区域），出岛从所选区域生成
- **探索规则**：翠湾区域内探索与灰冠完全一致（四档补给 60/70/80/90%、10 分钟、同成本同成功率）；曜原/霜环为「远洋探索」，需单独设计（边界已冻结：成功率更低且更难，具体数值后续决定）
- 本条冻结区域分配/解锁/选择/翠湾规则；远洋探索细节（成本/时长/成功率/结算）与曜原/霜环内容（植物池/商品池/特殊机制）待后续迭代确定
